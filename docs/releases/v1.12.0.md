# RuleScript v1.12.0

RuleScript v1.12.0 adds hover, document outline, and folding APIs for editor integrations, fixes import-aware navigation, and introduces the first version of the RuleScript Language Server.

## Editor APIs

`RuleScriptLanguageService` adds three APIs that work on any `RuleScriptDocumentAnalysisResult`, including tolerant results from `TryAnalyzeDocument`:

```csharp
var document = RuleScriptLanguageService.TryAnalyzeDocument(engine, source, @"eqp\crane.rules");

var hover = RuleScriptLanguageService.GetHover(document, line, column);
var outline = RuleScriptLanguageService.GetDocumentSymbols(document);
var folding = RuleScriptLanguageService.GetFoldingRanges(document);
```

### Hover

`GetHover` returns a `RuleScriptHoverInfo` for the symbol under the cursor, or null when there is none. `Signature` is a RuleScript-style declaration line:

```text
function AddOne(value: number) -> number
builtin function Substring(value: any, start: number, length: number) -> string
host function HostScore(playerId: string) -> number
(parameter) value: number
const LIMIT: number
```

`Documentation` contains `///` comments or Host Function documentation, `Range` covers the hovered occurrence, and `IsExternal` marks built-in and Host Functions.

### Document Symbols

`GetDocumentSymbols` returns a hierarchical outline of imports, functions, variables, and constants as `RuleScriptDocumentSymbol` values. Functions list their local declarations as `Children`, and `Detail` shows the signature, for example `@HostTrigger("LotArrived") (lotId: string) -> void`. Declarations that fail to parse are omitted, so the outline stays usable while a document is being edited.

### Folding Ranges

`GetFoldingRanges` returns `RuleScriptFoldingRange` values for `#region` blocks, multi-line statements and blocks, multi-line comments, and consecutive `///` documentation lines. Lines are 1-based and inclusive. For blocks, `EndLine` is the line of the closing keyword.

## Navigation Fixes

- Documents analyzed with `TryAnalyzeDocument(engine, source, sourceFile)` now resolve navigation imports relative to the source file, matching analysis. Previously, navigation always used `WorkingDirectory`.
- Imported files with syntax errors no longer make `GetDefinition` and `FindReferences` throw. Valid declarations in the imported file remain navigable.
- Symbols inside `parallel` task bodies now support definition and references.

## RuleScript Language Server

The repository now includes `RuleScript.LanguageServer`, a dotnet tool (`rulescript-lsp`) that serves RuleScript over the Language Server Protocol on stdio. It provides diagnostics, definition, references, hover, document symbols, folding ranges, and formatting. See [RuleScript.LanguageServer/README.md](../../RuleScript.LanguageServer/README.md) for installation and editor setup.

The language server is not yet published to NuGet. It is versioned separately from `RuleScript.Core`, starting at 0.1.0.

## Compatibility

No existing public APIs change. Script execution, strict analysis, and formatting output are unchanged.

## Validation

Regression coverage verifies hover for user, built-in, and Host Functions, parameters, and constants; hierarchical and incomplete-document outlines; region, block, and comment folding; parallel task navigation; and source-file-relative navigation into an imported file with syntax errors. Language server tests cover protocol mapping and an end-to-end JSON-RPC session.

The core test suite contains 666 tests, and the language server test suite contains 12 tests.
