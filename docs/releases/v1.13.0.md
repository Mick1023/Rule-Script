# RuleScript v1.13.0

RuleScript v1.13.0 adds completion and signature help APIs for editor integrations, and fixes navigation for `foreach` loop variables.

## Completion

`RuleScriptLanguageService.GetCompletions` returns completion candidates for a 1-based cursor position:

```csharp
var document = RuleScriptLanguageService.TryAnalyzeDocument(engine, source, @"eqp\crane.rules");
var completions = RuleScriptLanguageService.GetCompletions(document, line, column);

foreach (var item in completions.Items)
{
    Console.WriteLine($"{item.Kind} {item.Label} {item.Detail}");
}
```

Candidates depend on the cursor context:

- In code: parameters and variables in scope, user, imported, Host, and built-in functions, import aliases, keywords, and block snippets (`if`, `ifelse`, `foreach`, `while`, `function`, `switch`)
- After `alias.`: functions exported by the imported module
- After `@`: the `HostTrigger` attribute
- Inside strings and comments, where a new name is being declared (such as `var |`), and after members of runtime values (such as `payload.`): no candidates

Incomplete lines such as `var next = to` still produce candidates.

Each `RuleScriptCompletionItem` provides `Label`, `Kind`, `Detail` (for example `function Calc(rate: number) -> number`), `Documentation`, and `InsertText`. When `IsSnippet` is true, `InsertText` uses LSP snippet syntax such as `if ${1:condition} then:`, which Monaco and LSP clients expand directly. `RuleScriptCompletionList.ReplaceRange` covers the partially typed word that a selected candidate replaces. Clients filter candidates by that word.

Visible variables follow the existing `RuleScriptEngine.Analyze` cursor rules: all script-level variables plus the locals and parameters of the function containing the cursor.

## Signature Help

`RuleScriptLanguageService.GetSignatureHelp` describes the function call surrounding the cursor, or returns null outside a known call:

```csharp
var help = RuleScriptLanguageService.GetSignatureHelp(document, line, column);
var signature = help?.Signatures[help.ActiveSignature];
// signature.Label: "Substring(value: any, start: number, length: number) -> string"
// help.ActiveParameter: zero-based index of the argument under the cursor
```

Each `RuleScriptParameterInfo` reports its `Label` and its zero-based `Start` and exclusive `End` offsets inside the signature label, which map directly to LSP and Monaco parameter label ranges. The active parameter is tracked across nested calls, array and object literal arguments, and `alias.Function(...)` calls.

## Foreach Navigation Fix

`ForeachStatement` adds `VariableLine` and `VariableColumn` for the iterator variable name. Definition and references for loop variables now point at the variable instead of the `foreach` keyword. `Line` and `Column` are unchanged and still point at the `foreach` keyword, so runtime and analysis diagnostic locations stay the same.

## Language Server

The RuleScript Language Server adds `textDocument/completion` (triggered by `.` and `@`) and `textDocument/signatureHelp` (triggered by `(` and `,`). Snippet candidates are sent only to clients that declare snippet support.

## Compatibility

No existing public APIs change. Script execution, analysis diagnostics, and formatting output are unchanged.

## Validation

Regression coverage verifies completion scoping inside functions, incomplete lines, Host Functions, import members, attribute completion, suppression in strings, comments, declarations, and unknown members, and that every snippet produces parseable code. Signature help coverage includes label offsets, documentation, nested calls, literal arguments, import alias calls, and positions outside known calls. Loop variable navigation and the unchanged `foreach` diagnostic location are also covered.

The core test suite contains 689 tests, and the language server test suite contains 15 tests.
