# RuleScript v2.0.0

RuleScript v2.0.0 computes with `decimal` instead of `double`. Base-10 fractions are exact, and arithmetic errors stop the script.

This is a breaking release for host applications. See the [2.0 migration guide](../migration-2.0.md) for the checklist.

## Decimal Numbers

```rulescript
var sum = 0.1 + 0.2;          // 0.3
var same = sum == 0.3;        // true
var price = 19.99 * 3;        // 59.97

var total = 0;
foreach i in Range(0, 10):
    total += 0.1;
endforeach                    // total == 1
```

- Number literals, arithmetic, comparisons, and `switch` cases use `decimal`, with 28 to 29 significant digits in the range of about ±7.9 × 10²⁸.
- `1 / 0` and `5 % 0` throw `Division by zero.` instead of producing infinity or NaN.
- Results outside the range throw `Arithmetic result is outside the range of RuleScript numbers.`
- Literals outside the range are syntax errors.
- JSON numbers stay `decimal` through arithmetic. JSON numbers outside the range make `JsonParse` throw.
- Host numbers of any CLR numeric type are converted when a script computes with them. NaN, infinity, and `double` values outside the range throw.
- `Abs`, `Min`, `Max`, `Clamp`, `Round`, `Floor`, `Ceiling`, `Pow`, `Sqrt`, `Sum`, `Average`, and `DateDiff` return `decimal`. `Pow` and `Sqrt` compute with `double` internally, and results outside the range throw. `DateDiff` divides exactly, so a third of a day is `0.3333333333333333333333333333`.

## Number Text

Converting a number to text removes trailing zeros: `1.50` becomes `1.5`, and `2.0` becomes `2`. This applies to `+` with strings, template strings, `ToString`, `Join`, and `JsonStringify`. Use `FormatNumber(value, "0.00")` for a fixed number of decimals.

## Reading Numbers in the Host

`RuntimeValue.As<T>()`, `RuntimeContext.Get<T>()`, and `RuntimeContext.GetOrDefault<T>()` convert between numeric types:

```csharp
var count = context.Get<int>("count");      // decimal 3 → 3
var ratio = context.Get<double>("ratio");   // decimal 0.25 → 0.25
```

Reading a number with a fraction as an integer type throws `InvalidCastException`, and `GetOrDefault<T>` returns the default. Previously any numeric type mismatch threw `InvalidCastException`, including reading a JSON number with `Get<double>()`.

## Breaking Changes

- Script numbers are `decimal`. Host code that casts raw values, such as `(double)args[0]` in a `RegisterFunction` callback or `(double)context.Get("x")`, throws `InvalidCastException`. Use `Get<T>()`, `Convert.ToDouble`, or a `[RuleScriptFunction]` method with typed parameters.
- Division by zero and out-of-range results throw instead of producing infinity or NaN.
- Number text drops trailing zeros and no longer shows `double` rounding artifacts.
- `LiteralExpression.Value` holds a `decimal` for number literals.

## Performance

In a benchmark of 200,000 loop iterations, an arithmetic-heavy script ran in 62 ms versus 58 ms on 1.16.0, and a script mixing objects, comparisons, and conditions ran in the same time.

## Validation

Regression coverage verifies exact fraction arithmetic and comparison, literal types and range errors, text formatting across `+`, template strings, `Join`, and `JsonStringify`, division by zero and overflow with source locations, 28-digit division, conversion of host `int` and `double` values including NaN and infinity, Host Function arguments, numeric conversion in `Get<T>()` and `GetOrDefault<T>()`, JSON precision and range, decimal results from math and date built-ins, and decimal `switch` cases.

The core test suite contains 871 tests.
