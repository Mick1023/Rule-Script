# RuleScript v2.1.1

RuleScript v2.1.1 fixes editor navigation for overloaded functions. Built-in functions, user functions, and Host Functions all behave the same way.

## Hover and Go to Definition Pick the Called Overload

Before this release, hover and go to definition always showed the last overload registered under a name. For example, hovering `PadLeft("5", 2)` showed the three-parameter `PadLeft`.

Now both features use the overload that the call actually resolves to, the same one that runs at execution time:

- The argument count must match, and so must the argument types. `Describe(7)` goes to `Describe(value: number)`, and `Describe("ok")` goes to `Describe(value: string)`.
- Hovering or going to definition on an overload's own declaration shows that declaration, not the last one.
- When a call cannot be resolved by type, the overload is picked by argument count. This covers calls with errors, ambiguous calls, and calls inside imported files.

```rulescript
var a = PadLeft("5", 2);       // builtin function PadLeft(value: any, totalWidth: any) -> string
var b = PadLeft("5", 2, "0");  // builtin function PadLeft(value: any, totalWidth: any, padding: any) -> string
```

## Find References and Rename Follow One Overload

`RuleScriptLanguageService.FindReferences` on an overloaded function now returns only the declaration and calls of that overload. Before, it returned every call to every overload with the same name.

`RuleScriptLanguageService.Rename` uses the same references. Renaming one overload now renames only that overload and its calls, the same as C#. Functions without overloads, variables, and parameters are unchanged.

There are no public API changes.
