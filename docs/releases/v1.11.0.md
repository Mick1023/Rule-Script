# RuleScript v1.11.0

RuleScript v1.11.0 prepares the core library for language server and editor integrations. Documents that are still being edited can now be analyzed without throwing, lexical errors are recoverable, and parsed AST nodes carry complete source ranges.

## Tolerant Document Analysis

`RuleScriptLanguageService.TryAnalyzeDocument` analyzes incomplete or invalid documents and reports syntax errors as diagnostics instead of throwing `SyntaxException`:

```csharp
var document = RuleScriptLanguageService.TryAnalyzeDocument(engine, source, @"eqp\crane.rules");

if (!document.Success)
{
    foreach (var diagnostic in document.Diagnostics)
    {
        Console.WriteLine($"{diagnostic.Line}:{diagnostic.Column} {diagnostic.Message}");
    }
}

// Navigation keeps working on the valid parts of the document.
var definition = RuleScriptLanguageService.GetDefinition(document, line, column);
```

Overloads accept a `RuleScriptEngine` for Host Function metadata and an optional source file used to resolve relative imports.

`RuleScriptDocumentAnalysisResult` adds:

- `Diagnostics`: every syntax and semantic diagnostic for the document
- `Success`: whether the document was parsed and analyzed without error diagnostics

`RuleScriptAnalysisCache.GetOrTryAnalyze(documentId, source)` provides the cached tolerant variant for editor change notifications. `GetOrAnalyze` never returns a tolerant result, so it continues to throw for invalid source.

`AnalyzeDocument` remains strict and continues to throw `SyntaxException` for syntax errors.

## Recoverable Lexical Errors

Tolerant analysis now keeps scanning after lexical errors and reports each one as a diagnostic:

- unsupported characters and a lone `?` are skipped
- unsupported string escapes keep the escaped character
- unterminated string literals keep the partial text
- unterminated multi-line comments are closed at the end of the document

Script execution and strict analysis are unchanged and still stop at the first lexical error.

## Source Ranges

`Statement.Range` and `Expression.Range` expose the full `RuleScriptSourceRange` covered by each parsed node:

```csharp
var statement = (VarStatement)document.Statements[0];
var range = statement.Initializer?.Range; // start and exclusive end, 1-based
```

## Behavior Changes

- `Token.Line` for multi-line comments now reports the start line. It previously reported the end line. `Token.EndLine` and `Token.EndColumn` now report the real end position of multi-line tokens.
- `RuleScriptEngine.TryAnalyze` now uses the recovering lexer. A lexical error may produce several diagnostics, ordered by source position, instead of exactly one, and the returned symbols come from full partial analysis.
- AST `Expression` records now store their source range, so record equality and `ToString()` include position information. This matches the existing `Statement` behavior. Two expressions with the same content at different positions are no longer equal.

Script execution, strict `Analyze`, `AnalyzeDocument`, formatting output, and debugging are unchanged.

## Validation

Regression coverage verifies lexer recovery, multi-line token positions, tolerant document analysis and navigation, diagnostic ordering, expression and statement ranges, and analysis cache behavior.

The complete test suite contains 657 tests.
